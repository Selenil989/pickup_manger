# 1. Think Before Coding

구현 전에 반드시:

* 현재 상태를 파악한다.
* 가정을 명시한다.
* 불명확한 부분은 질문한다.
* 더 단순한 방법이 있으면 제안한다.
* 확신이 없으면 구현하지 않는다.

---

# 2. 설계 우선

절대로 구현부터 시작하지 말 것.

작업 순서:

1. 현재 상태 분석
2. 문제점 정리
3. 수정 계획 제시
4. 예상 영향 설명
5. 승인 요청
6. 구현
7. 변경 내용 보고

내 승인 전에는 절대로 수정하지 말 것.

---

# 3. 범위 확장 금지

요청하지 않은 기능은 만들지 말 것.

금지:

* 무단 기능 추가
* 무단 구조 변경
* 무단 리팩토링
* 무단 라이브러리 추가
* 무단 파일 생성

---

# 4. 최소 구현 원칙

최소한의 코드로 해결할 것.

* 단일 사용 코드에 추상화 금지
* 미래를 위한 구조 추가 금지
* 사용하지 않는 설정 추가 금지
* 사용하지 않는 유연성 추가 금지

항상:

"이 코드가 과한가?"

를 검토할 것.

---

# 5. Surgical Changes

수정 범위 최소화.

* 요청과 관련 없는 코드 수정 금지
* 기존 스타일 유지
* 기존 기능 유지
* 기존 정상 동작 기능 보호

변경한 모든 줄은 요청과 직접 연결되어야 한다.

---

# 6. 기존 기능 보호

완성된 기능은 절대 망가뜨리지 말 것.

새 기능보다 기존 기능 보호가 우선이다.

수정 시 반드시 설명:

* 무엇을 수정하는가
* 왜 수정하는가
* 기존 기능에 영향이 있는가

---

# 7. Goal Driven

모든 작업은 검증 가능한 목표로 변환한다.

예시:

버그 수정
→ 재현
→ 수정
→ 검증

기능 추가
→ 목표 정의
→ 구현
→ 테스트
