# 재화 거래 내역(영수증) 기능 — 설계

작성: 2026-08-23 · 상태: 설계 확정 대기(사용자 검토)

## 1. 목적

보유 재화를 **언제 얼만큼 얻었고 얼만큼 소모했는지** 시간순으로 **영구 기록**하고,
버튼을 누르면 **영수증처럼** 조회한다. 계정별로 저장되어 기기·세션과 무관하게 남는다.

## 2. 데이터 모델

- 저장 위치: `pickup_manager_ledger_<gameId>` (게임별 JSON 배열, **append-only**)
- 기존 재화 데이터와 동일하게 localStorage에 저장 → `auth.js`의 setItem 후크가
  `pickup_manager_*` 키를 계정별 Supabase(`user_data`)에 자동 업로드 → **영구·계정별**. 별도 인프라 없음.

각 항목:

| 필드 | 설명 |
|------|------|
| `ts` | 타임스탬프 (epoch ms) |
| `type` | `'auto'`(잔량 변동) 또는 `'memo'`(수동 메모) |
| `currency` | 재화 id. auto는 필수, memo는 선택 태그 |
| `delta` | 변동분(+획득/−소모). **auto만** |
| `balanceAfter` | 변동 후 잔량. **auto만** |
| `memo` | 사유/메모 텍스트. auto=선택, memo=필수 |

## 3. 기록 방식 (혼합)

- **자동 — 금액 기록의 유일한 원천**
  - 재화 설정 모달에서 수량을 저장하면, **바뀐 재화별로** `{type:'auto', currency, delta:신−구, balanceAfter:신}` 을 원장에 추가.
  - 여러 재화가 동시에 바뀌면 각각 한 줄씩. 변동 없는 재화는 기록 안 함.
- **수동 — 메모만 (잔량 안 건드림)**
  - "메모 추가"로 `{type:'memo', ts, memo, currency?}` 추가. **금액·잔량 없음.**
  - 맥락 기록용 (예: "월정액 결제함", "여기서 아케론 확정 지름").
- 모든 항목의 `memo`는 나중에 **수정 가능**.
- **삭제 없음** (영구 보존 요청 반영). 항목은 append-only.

## 4. 잔량(running balance)

- `auto` 항목의 `balanceAfter`가 그 시점의 실제 잔량 → 영수증 잔량 컬럼에 표시.
- `memo` 항목은 잔량 변동이 없으므로 잔량 컬럼에 `—` 표시(직전 잔량 유지).
- 원장의 auto delta 누적이 곧 현재 잔량과 일치(잔량이 원장의 근거).

## 5. UI / 영수증

- 재화 페이지에 **"내역"(영수증) 버튼** → 모달.
- **최신순 타임라인**:
  - auto 행: `날짜 · 재화 · +N/−N(초록/빨강) · 잔량`
  - memo 행: `날짜 · 📝 메모 텍스트` (구분되는 스타일)
- 상단 요약: 표시 범위 **총 획득 / 총 소모**.
- 하단: **"메모 추가"** 버튼.
- (v1은 전체 목록. 재화별 필터는 v2 여유 시.)

## 6. 코드 연동 지점

- 재화 저장 함수(현재 currency config 모달 save)에 **델타 계산 + 원장 append 후크** 추가.
- `renderCurrencyPage`에 "내역" 버튼 + 원장 모달 렌더/이벤트.
- 원장 로드/저장 헬퍼: `loadLedger(gameId)` / `appendLedger(gameId, entry)` (localStorage).

## 7. 범위 밖 (YAGNI)

- 항목 삭제, 재화별 필터(v2), 백엔드/프록시, 게임 자동연동, **수동 금액 거래**(수동은 메모만).

## 8. 성공 기준

- 재화 수량을 바꾸면 그 변동이 자동으로 원장에 남는다(획득/소모 부호 정확).
- "내역" 버튼으로 시간순 영수증(날짜·재화·±금액·잔량)이 보인다.
- 수동 메모를 추가·수정할 수 있고, 잔량은 안 바뀐다.
- 로그아웃/재로그인·다른 기기에서도 기록이 유지된다(계정 동기화).
- 항목은 삭제되지 않는다(영구).
